# Idiomas (i18n)

Como o bot carrega os catálogos de tradução, como adicionar um idioma e o que a checagem do CI recusa.

## Onde ficam

`empiremuse/locales/<locale-do-Discord>/{commands,bot,panel}.json`, por exemplo `en-US` e `pt-BR`. O nome da pasta é o código de locale do Discord. `en-US` é a referência: toda chave nasce nele.

## Regras das chaves

- Formato `^[a-z0-9_]+(\.[a-z0-9_]+){1,6}$`, até 128 caracteres.
- Plural por sufixo: `_zero`, `_one`, `_two`, `_few`, `_many`, `_other`. O `pt-BR` exige `_many` (regra do CLDR).
- Placeholders só no formato `{nome}`.
- Chaves de comando: `cmd.<caminho>.description`, `cmd.<caminho>.opt.<base>.name`, `.description` e `.choice.<valor>`. A legenda de um grupo fica em `cmd.<grupo>._label`.

## O que é descartado

O validador descarta a entrada (o resto do arquivo continua valendo) quando ela tem:

- `@everyone`, `@here`, `<@`, `<@&`, `<#`, `</` ou `<id:`;
- links fora do que o `en-US` tem;
- markdown diferente do `en-US`;
- placeholders `{nome}` diferentes dos do `en-US`;
- caracteres bidi, invisíveis ou de controle;
- texto acima do tamanho do tipo (por exemplo, 100 caracteres na descrição de comando e na escolha, 80 na legenda, 150 no placeholder, 45 no título de modal, 256 no título);
- nome de opção que não seja minúsculo, com 1 a 32 unidades UTF-16, só com letras e dígitos **de qualquer escrita** (como `posição`) ou `-`, `_` e `'`.

## Adicionar um idioma

1. Crie `empiremuse/locales/<locale>/` com os mesmos arquivos do `en-US`.
2. Traduza as chaves; as que faltam usam o `en-US`.
3. Com **90% ou mais** de cobertura o locale liga sozinho; abaixo disso fica desligado. `en-US` e `pt-BR` precisam de 100%.
4. Rode a checagem (abaixo).

## Checagem local e no CI

```bash
python -m empiremuse.i18n.check [--root DIR]
```

Usa o mesmo validador do `BotPool`. Sai com código diferente de zero se houver arquivo recusado ou entrada descartada em qualquer locale, se `en-US` ou `pt-BR` ficarem abaixo de 100%, ou se o código usar `tr("…")` ou `localized("…")` com uma chave literal que não existe no `en-US`. A saída tem um resumo de cobertura por locale (contagens) e, para cada problema, uma linha `ERRO` com a chave e o motivo, nunca o texto do catálogo.

No CI o passo "Verificação dos catálogos de idioma (i18n)" roda no job `ci`, depois da compilação, quando o código muda. A dependência `babel` vem do `requirements-lock.txt` com hash.

## Crowdin (configuração do projeto)

O `crowdin.yml` liga os três catálogos `en-US` (origem) ao Crowdin com o tipo `json`. O `pt-BR` **não** entra no Crowdin: o time o escreve só no repo (ele tem chaves `_many` que o `en-US` não tem, e o Crowdin não exporta chave sem origem). A exportação (`export_languages`) leva os 30 locales do Discord que não são `en-US` nem `pt-BR`.

Passos do dono na interface do Crowdin, nesta ordem (a integração com o GitHub lê estas opções do projeto, não do arquivo):

1. **Settings > Languages > Source Language**: troque para **English (United States)** e clique em Update. O Crowdin permite mudar o idioma de origem com o projeto já criado; o aviso dele é sobre formas de plural que podem não bater, por isso o passo 3 reenvia as origens.
2. **Files**: apague os três arquivos de origem antigos (`pt-BR/commands.json`, `bot.json`, `panel.json`). O projeto ainda não tem tradução de verdade (o PR #194 só trouxe texto de origem), então nada se perde.
3. Mescle o PR do `crowdin.yml` no `main` (no fim, junto da versão) e deixe a integração com o GitHub subir os arquivos `empiremuse/locales/en-US/*.json` como origem.
4. **Settings > Languages > Target Languages**: deixe só os locales do Discord, **sem `pt-BR` e sem `en-US`**. Remova também `af-ZA`, `ar-SA`, `ca-ES`, `he-IL` e `sr-SP`.
5. **Settings > Export > Skip untranslated strings**: ligado. Sem isso o Crowdin enche o arquivo com o texto de origem (em inglês) e o bot ligaria o idioma com 90% de cobertura falsa. Em JSON a chave pode sair com valor vazio; o bot trata vazio como "sem tradução" e cai no `en-US`.
6. **Skip untranslated files**: desligado (ele anula o item 5 e só exporta idioma 100% traduzido).
7. Feche o PR #194 e confira o primeiro PR novo da l10n: nenhum idioma com texto em inglês ou português fingindo tradução, nenhuma pasta `pt-BR` ou `en-US` nele e nenhuma chave de plural perdida.

### Erro no texto em inglês

A origem é o `en-US` do repo; a comunidade não a edita no Crowdin. Quem achar erro no inglês comenta na própria string (Editor > Comments) ou abre uma "Source string issue" (tipo "Mistake in the source"). O time lê isso no projeto e corrige em `empiremuse/locales/en-US/` num PR normal; a correção chega ao Crowdin quando a integração com o GitHub sincroniza a origem. Mudança no `en-US` que muda o sentido pede revisão do `pt-BR` na mesma PR.
